# 参数事务与权限授权

> [English](parameter-service.md)

此可选框架接口现有确定性的参考 App 与复制展示见证。既有生产 Product、原生工作线程、CAN 编码器、SDO 通道及 NVM 后端仍未绑定。优先级继续由[维护计划](maintenance-plan.zh-CN.md)维护。

## 所有权与身份

App 所有者独占调用 `runtime/meter_parameters.h` 和 `runtime/meter_authorization.h`。无锁、回调、内存分配、设备调用或线程。调用方在整个生命周期内持有服务和不可变目录。禁止复制、移动或重新初始化活动服务：已有请求账本指向其内嵌结果槽。目录、服务及调用输入/输出存储不得重叠。

每个服务接纳一个事务，保留终态直到确认领取。这是串行化/结果信用边界，不限制平台参数总数。目录长度由调用方提供；初始化检查全部属主+ID。独立后端通道可拥有独立服务及不同非零请求会话。旧响应仍可能存在时不得复用会话；集成者负责跨复位的会话分配。序号及授权代次耗尽时拒绝继续，不回绕。

`meter_parameter_key_t` 标识逻辑 Product 端点及参数，不编码总线、原始 CAN ID、SDO index/subindex 或存储偏移。不同属主可使用相同数字 ID；完整键重复及属主为零被拒绝。`meter_parameter_definition_t` 独立于现有本地设置目录 `meter_parameter_def_t`，MSP2 持久化和身份均不改变。

## 目录就绪状态与权限

零初始化描述符是未确认状态，不能读写。仅当映射、表示、访问和边界有证据时，Product 才能确认条目。已确认的可写描述符必须有非零权限掩码；已确认范围必须有限且有序。未知条目返回 NOT_FOUND，未确认条目返回 UNCONFIRMED，均在预留身份或派发前拒绝。通用样例仅包含合成数据。确认是 Product 声明，不自动证明硬件已就绪。

数值采用有限工程单位浮点数，与当前 Domain 数值约定一致。要求无损的宽整数、浮点无法表示的位域、字符串和不透明块不在本接口范围。后端必须拒绝无法表示的转换，不得静默舍入私有线上编码。上下界不代表步长、枚举集合、出厂默认值、缩放或写入/回读策略；这些需要提交前执行已确认的 Product 校验。

授权包含权限位、单调递增代次和到期时间，凭据留在 Product。公开读取可要求零权限；受保护操作在准入、派发、超时处理及回复处理时均要求全部声明权限位。再次授权生成新代次，撤销后重授不能复活旧事务。无效授权输入保留原授权；显式撤销始终清除权限，代次耗尽也有效。同一事务的所有调用必须使用同一个逻辑授权。

时间采用单调毫秒。间隔非零且小于 `contracts/meter_time.h` 的半周期范围。App 必须在比较窗口内处理期限，并在超出该窗口前撤销过期授权；本辅助器不是墙上时钟凭据数据库。到期瞬间拒绝访问。受保护写在派发后失去权限时可能已经生效，结果是不确定而非已回滚。现有 Demo 授权和健康模式策略保持不变。

## 事务生命周期

| 阶段 | App 操作 | 结果信用 / 效果 |
|---|---|---|
| 空闲 | `submit` 校验键、确认状态、权限、范围和策略 | 复用 `meter_requests` 账本预留身份与结果槽 |
| 排队 | `take` 重新检查权限/期限，启动账本并复制工作 | 派发边界，之后后端可能执行 I/O |
| 等待 | `reply` 校验 ID、属主+ID、操作及尝试号 | 忽略错误关联，已关联但格式无效的内容终结为 INVALID_REPLY |
| 重试就绪 | 总期限内由 `tick` 结束一次读尝试 | 下次 `take` 在同一请求身份下递增尝试号 |
| 终态 | `query` 复制结果，`acknowledge` 释放结果信用 | 重复查询稳定，确认前不接纳新请求 |

总超时从准入开始，含排队时间。尝试超时从 `take` 开始，含后端排队延时。总超时优先于重试，在期限瞬间到期。写仅允许一次尝试；多次读尝试必须显式声明 `repeatable_read`，因为有些读有副作用。自动重试只针对尝试超时，不针对后端明确拒绝/失败。迟到回复不能完成过期尝试。

结果区分成功、超时、权限丢失、调用者取消、远端拒绝、已关联但无效的回复及传输失败，包含复制的请求/尝试号、可选已校验值和后端详情。已派发写的取消、超时、无效回复或传输失败标记 `effect_unknown`。REJECTED 仅用于后端确认没有生效的拒绝；不能确定时应返回传输失败。OK 表示后端已确认操作完成，不普遍保证回读或耐久性。要求耐久的本地设置适配器必须等到存储确认后才报告 OK。

内部账本仅提供预留/保留机制，其通用取消码不是参数结果；调用者使用 `meter_parameters_query`，不得读取内嵌账本。结果不改变全局模式或 Domain 故障，由 App 决定呈现和分类。`query` 支持轮询或把终态复制到现有所有者 IPC，不隐式创建回调线程。

## 后端集成责任

后端接收复制的 `meter_parameter_work_t`，通过现有所有者 IPC 返回复制的回复。构造回复前必须校验线上长度、格式、来源、总线、键/操作映射、表示及实际完成情况。本地请求 ID 无法识别未携带标签的迟到线上响应。适配器必须在接受新尝试或请求前串行化并排空/隔离歧义旧响应，不得给任意匹配帧套上当前活动 ID。

取消和确认领取结果不会取消、排空或释放后端 I/O 资源；后端生命周期可能长于调用者关注期。通道排空时可以延后 `take`，总超时仍继续。每种适配器在生产接线前均需迟到回复、取消及资源的确定性测试；读重试同样要求隔离契约。此处不推断总线分配、私有校验和、CANopen 对象字典、重试时序或真实控制器策略。

标定应是基于新鲜 Domain 测量和类型化参数结果的 App 工作流。前置条件、来源新鲜度、写结果不确定性、可选回读及用户通知保持显式，不把事务放在 LVGL handler。计数累积/迁移、动态控制器能力及共享身份提供者仍为活动计划中的独立待办。

## 验证与限制

`tests/test_parameters.c` 覆盖属主限定键重复、未确认数据、准入失败原子性、权限掩码/到期/重授、时钟回绕、错误回复、结果保留、读重试、排队/活动取消、写结果不确定性及身份耗尽。`tests/test_product_boundaries.c` 描述现有双总线路由、超时后的值/来源保留、恢复和独立 20/50 ms 调度。合成期限不构成物理 CAN 时序证据。

通过 CTest 执行 `parameter-contracts`、`product-boundaries`、`guard-boundary-fixtures` 和 `assertion-witness`。Debug 和 Release 均保留测试断言。完整选定 Product 矩阵与实际限制记录在维护计划中，不宣称当前源码固件、控制器互通、HIL、迁移或标定已验收。

## 参考 App 与展示边界

`examples/parameter-workflow/app.c` 是可选参考 App 所有者，仅由 CTest 见证链接。它把既有事务服务和授权与三个非阻塞复制消息端口组合：ready、send、receive。真实 Product 通过协议所有者 IPC 实现端口；参考实现不选择 CAN、不编码帧、不加载凭据、不改变生产 App 回调 ABI。它不是链接进固件的额外 Product。

App 消费值意图：配置代数、面板生命周期令牌、属主限定键、操作及期望值。旧配置代数或零面板令牌在准入前失败。超时/重试策略由 App 所有，UI 无权更改。App 所有权下的认证代码发放/撤销授权。每次 App step 处理期限，最多消费一个回复，在后端就绪时最多派发一次尝试，再把终态复制到展示值。step、意图及确认处理须串行，使用已初始化对象、不重叠输出存储及有效的非阻塞端口回调。

`ui/presentation.h` 只有值契约。pending 不代表成功，不包含乐观的已确认值。UI 仅在配置代数和面板令牌匹配且 `has_result` 为真时渲染结果。派发后取消/超时的写入可能已生效，须保留 `effect_unknown`，不能显示已回滚。结果详情不改变整机健康状态。终态保留到 App 收到同时匹配面板令牌及请求身份的确认。被替换面板可忽略旧结果，但 App 仍须显式确认；忽略发布不会释放结果额度。由 Product 策略决定谁确认已离开面板的结果。

后端 ready 独立于 UI 结果额度，包含资源所有权及排空/隔离。取消或确认写入后后端仍忙。新意图可获准入，但后端释放通道前不能派发，总期限仍推进。测试后端在延迟完成时返回原复制令牌，绝不把新请求盖到旧回复上。ready/send 竞态若在 `take` 后拒绝交接，参考实现保留 TRANSPORT_FAILED 及保守的写入不确定性，不重发写入。真实适配器仍需线上关联/排空证据。

`tests/test_parameter_app.c` 验证准入及属主特定范围、旧配置/面板过滤、输入输出复制生命周期、结果保留、派发前授权到期、派发后撤销再授权、后端仍持有资源的取消、新请求期间的旧完成、队列拒绝、排空后的读重试、畸形回复及排队总超时。全部输入回复为合成值。原 `parameter-contracts` 继续覆盖更广的身份、时钟回绕及结果矩阵。Debug 和 Release 使用 `ctest --test-dir BUILD --output-on-failure -R parameter`。

生产集成决策：后端映射及生命周期/关联规则确认后，才绑定 Product 专属描述符、认证及语义 IPC 端点。每个镜像始终仅一个 Product。目录/配置替换须先明确会话分配、在途取消、资源排空和保留结果，再重新初始化；参考实现有意不提供在线复位捷径。本地 Settings/MSP2 及静态授权布尔值仍独立，见维护计划 D-06。
