# Application 服务与 Product 展示

## 所有权与兼容性

Domain / Runtime 状态经 Product Application 服务和强类型 Product 展示值进入 LVGL。Demo 的 products/demo/application/presentation.c 可脱离 LVGL 构建，把已有一致快照投影为自有标量、有效状态及不可变目录字符串。屏幕渲染值并发送意图；本地 Setting 意图与确认状态分离。不增加响应式引擎、第二套快照传输、线程或锁。未知/过期/错误不会成为有效零值。保持既有单位、阈值及本地设置策略；设置不可用时不再用零静默覆盖控件。

Product manifest 可选 application 组由 CMake 与固件的同一个 METER_PRODUCT_ROOT 选择。每个固件仍只包含一个 Product。参数参考示例和合成标定夹具属于 Host 证据，不是固件内额外 Product 或生产传输绑定。

meter_snapshot_t 增加内存 profile 字段。所有使用方应一起重编译；这不是预编译调用方的稳定二进制 ABI。MSP2 序列化、CAN 编码、线程所有权、调度、升级信任及原生失败行为不变。Product 显式提供映射前 Demo 动态 profile 保持未知，不因此隐藏既有静态 Demo 页面。

## Profile 发布与使用方

仅 App 将 Product 原始身份/特征映射为 meter_profile_t：确认的稳定 family、归一化能力及 generation。family 为零/未确认表示没有可用动态 profile。meter_core_profile 拒绝畸形状态和代际耗尽，同值刷新不变，语义变化递增 generation/revision。代际不回绕；会话重启是新生命周期，不允许复用旧面板/后端 token。Profile 随既有加锁深拷贝快照发布。setter 是 App 串行代码，不是跨线程原子 API。

发布变化的 profile 前，Product App 必须在同一轮 App 中使关联测量、故障目录、身份/版本缓存和展示选择失效。不能给旧测量重新贴新 generation。Core 无法推断 Product 依赖，因此不清除无关信号。合成 Product 映射夹具证明原始特征位止于适配层，通用代码只看到归一化值。

| 使用方 | 必需处理 |
|---|---|
| 展示 / 功能可见性 | 比较 generation，从当前复制快照重建；未确认动态能力不可用 |
| 参数面板 | 同时匹配面板生命周期 token 与 profile generation；旧结果保留原身份 |
| 标定 | 证明测量采集 generation；拒绝过期/不匹配采集；profile 变化使活动流程失效 |
| 故障目录 / 版本缓存 | 下次发布前将旧解释标记不可用；Product 选择目录和重新获取策略 |
| 后端 | 独立持有未完成请求/隔离额度；关闭 UI 或更换 profile 不等于线路取消 |

参考参数 App 更换 profile 时显式取消调用方兴趣并撤销授权。这是合成示例策略，不是生产安全决策。旧的成功或不确定结果仍是历史结果，不能作为当前 profile 成功。D-07 仍要求 Product 评审缓存失效、认证及线端响应关联。

## 采集与远程标定

runtime/meter_calibration 是可选的 App 自有服务，一次执行采集/写入/可选回读。Product 提供同工程单位的源与 owner-qualified 目标、时效上限、前置条件、授权及事务策略。服务没有传输、UI、持久状态或凭据。只初始化一次，在 App 串行调用，不复制活动服务。contracts/meter_calibration.h 仅包含复制的展示数据。

Begin 捕获一个有限 VALID 值，按半范围时间规则检查年龄、确认 profile 及测量代际证明，再受理写入。Step/take 复查代际、前置条件和授权；排队采集在派发前会过期。派发后刻意保持捕获值稳定。Take 要求后端另有就绪/排空额度。回复带既有精确事务身份；迟到/外来回复不能完成替代流程。不增加写重试。

DONE 保留独立强类型写入/回读结果，直到精确 generation/token 确认。派发后取消、profile 丢失、权限过期、传输失败和超时都保留 effect_unknown：写入可能生效，不是回滚。写成功而回读失败/不匹配仍可观察。解释终态前须检查 phase。旧 DONE 不再变动；使用方必须拒绝过年代际。派发前授权过期不会产生不确定写入。

合成测试覆盖无效/过期/未知/未来测量、时钟回绕、排队过期、畸形配置、代际更换、前置条件、真正授权到期、拒绝、超时、传输失败、可选/无回读、不符、迟到回复和面板确认。不证明客户映射、真实传感器新鲜度、ECU 行为或物理标定精度。

## D-01 分类决策

meter_parameter_classify 是纯强类型映射。预期抑制、通信过期、远端拒绝、超时、传输失败、资源压力、持久化失败及契约违反使用不同词汇。非参数事件来源不自动接入策略。分类器不修改全局模式；语义拒绝不会自动成为 DEGRADED。

| 类别 | 接入健康策略前待决策 |
|---|---|
| 预期抑制 / 远端拒绝 | 通常局限操作；确认 Product 策略与诊断可见性 |
| 通信过期 / 超时 / 传输失败 | 定义必需来源、持续时间、恢复及安全相关性 |
| 资源压力 / 持久化失败 | 定义有界恢复、耐久要求和升级阈值 |
| 契约违反 | 定义故障安全行为、复位权限及保留证据 |

D-01 保持待人工/Product 评审：连接 NORMAL/DEGRADED/FAULT 前批准事件到模式映射、滞回及恢复所有权。既有健康行为不变。这不是 DTC 子系统。

## D-05 计数器决策

未实现持久计数器服务。下列提议使决策有明确边界；其中 Product 策略值尚未批准。

| 主题 | 提议契约及待决策 |
|---|---|
| 累积单位 | 工时采用无符号 64 位毫秒；里程采用整数距离和保留小数余量；确认距离量子及传感精度 |
| 激活 | Product 提供明确钥匙/座椅/工作谓词及有效新鲜速度；逐计数器决定缺失/过期源行为 |
| 溢出 | 饱和并暴露终态诊断，绝不回绕；批准寿命/范围和恢复 |
| 复位 | 总里程/工时不隐式复位；独立小计/保养计数需显式授权和审计策略 |
| 间断 / 掉电 | 不积分无界间隙；定义最大间隔及自耐久检查点起可接受丢失量 |
| 检查点确认 | 分别跟踪请求、RAM 和耐久 revision；提交不是持久化成功 |
| 表示 / 版本 | 固定位宽版本化记录及迁移/默认策略；不保存原生 struct，本批不改变 MSP2 |
| 磨损预算 | 从器件耐久、每次字节数、寿命及可接受丢失推导检查点策略；无统一 Flash 周期 |

D-05 保持待批准语义及实际器件耐久证据。App 使用存储服务契约，不依赖 NOR/NAND/EEPROM 几何。D-03 部分初始化、一次性 shutdown、无界耐久/确认等待保持已刻画且未修改。

## 身份提供器评估

不可变固件/build 元数据和动态控制器身份生命周期不同。未来小型只读 Product identity view 应携带强类型来源、可用性、generation 及有界文本/值存储，供诊断/UI/维护复制。Update 保持可信兼容性检查。不统一 SDO、CAN 或固件元数据线端表示。暂不添加共享 provider：增加公开契约前先确认首个 Product 使用方及 profile 失效策略。D-07 记录这一待集成决策。
