# Forklift Meter Platform v0.3 — Phase 1

> [中文版](v0.3-phase1-domain.zh-CN.md)

## Phase

Domain semantics hardening.

## Changed

- `meter_core_apply()` compares the complete value and increments `revision` only when value, timestamp, state or source changes.
- `meter_core_tick()` uses each signal's `stale_ms`; zero disables automatic timeout and there is no runtime-wide fallback timeout.
- Stale transitions, connection/generation changes, parameters, faults and settings all update `revision` only on real state changes.
- Source arbitration receives complete incoming/current `meter_value_t` values, including timestamp, state, value and source identity.
- Existing product and host call sites use the two-argument `meter_core_tick(core, now_ms)` API.

## Tests

- `ctest --test-dir build --output-on-failure`: 21/21 passed.
- Core regression covers repeated identical signal/parameter/fault writes, stale transition revision, and source arbitration.
- Existing architecture, public-clean, DBC, bilingual UI, fixture and SDL tests remain green.

## Known limitations

- CANopen PDO/SDO and custom transaction services are not part of this phase.
- No board image was rebuilt for this host-only Domain change.
- The SDK `origin` URL remains the existing unavailable `boa-w` repository and was not changed.

## Next

Formalize the protocol framework with typed Event, Command and Transaction paths, then add the independent CANopen-style adapter and Reference-Mixed product.
